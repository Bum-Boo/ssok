# 설정·테마·언어 경험 검토안

2026-09-30. **제안이며 아직 채택된 ADR이나 구현 완료 계약이 아니에요.** 사용자 질문에 따라 설정과 화면 경험에서 필요한 기준을 정리했어요. 현재 동작과 실제 화면은 [소스별 감사](SETTINGS_UX_AUDIT_2026-09-30.md)를 먼저 확인하세요. 이 문서의 기능을 STATUS의 구현 목록에 그대로 넣지 않아요.

## 설정의 위치와 범위

언어는 현재처럼 상단에서 바로 찾을 수 있게 유지하고, 나머지 개인 선호는 한 설정 입구에서 찾도록 제안해요. 설정을 첫 사용의 필수 단계로 만들지 않아요.

| 묶음 | 제안 항목 | 이유 |
|---|---|---|
| 언어 | 운영체제 기본값, 명시적으로 선택한 언어, 지원 범위 안내 | 익숙한 언어로 빠르게 복구 |
| 화면 | 시스템 외관 기본값, 지원 환경에서 밝은/어두운 외관, UI·코드 글자 배율 | 교실 조명과 사용자 시력 차이 |
| 소리와 연출 | 효과음 음소거/음량, 불필요한 UI 움직임 줄이기 | 수업 방해·감각 부담 줄이기 |
| 조작과 도움 | 단축키·카메라 조작 안내, 포커스 표시 | 입력 장치를 바꿔도 사용 가능 |

설정은 이미 있는 자동 감지 기능을 불필요하게 다시 묻지 않아요. AI 제공자·비용·전송 데이터는 [기존 정책](POLICIES.md)의 별도 계약을 따라요. 로봇·과제의 설정과 개인 화면 선호를 같은 저장 데이터로 취급하지 않아요.

## 언어 전환

- 언어 이름은 `한국어 / 简体中文 / 日本語 / English`처럼 해당 언어로 표시해요. 국기로 언어를 대신하지 않아요.
- 선호 저장 → 운영체제 언어 → 지원하지 않을 때의 기본 언어 순서를 명시해요. 현재는 모든 `zh` 지역을 간체로 정규화하므로 번체권 처리 방침을 따로 정해요. 번체 지원을 주장하지 않아요.
- 정적 버튼, 블록 제목, 동적 상태, 툴팁, 열린 메뉴·대화상자까지 같은 전환을 따라야 해요. 이미 번역한 문자열을 다시 번역하는 대신 원문 키와 형식 인수를 보존해요.
- 학습자 코드·변수·프로젝트 이름·입력값은 번역하지 않아요. 그래프, 배선, 코드, 미적용 블록 초안, 선택 탭과 작업 상태를 보존해요.
- 키보드로 바꾸면 선택기에 포커스를 유지하거나 명확한 다음 위치로 복원해요. 단순히 포커스를 해제해 로봇 이동 단축키가 활성화되는지 확인해요.
- 저장 실패 시 현재 적용과 다음 시작의 저장 실패를 구분해 알려요. 웹의 저장 가능 여부와 새로고침은 실제 브라우저에서 별도로 검증해요.

## 테마와 읽기

배경·표면·본문·보조문구·강조·경고·성공·포커스의 의미별 토큰을 정본으로 둬요. 기존 `SsokTheme`의 중앙 팔레트를 확장하고 컴포넌트마다 새 색을 흩어놓지 않아요. 밝은 테마를 색상 반전으로 만들지 않아요.

시스템 외관을 기본으로 존중하는 방향을 제안해요. 시스템/밝게/어둡게의 앱 내 선택을 제공할지는 플랫폼·사용 맥락에 맞춰 정해요. Apple 지침은 시스템 설정 중복을 피하도록 하므로 앱 내 3가지 선택을 보편적인 의무로 해석하지 않아요. OS 감지와 웹 지원 가능성은 구현 전에 확인해요.

UI 외관을 바꿔도 3D 부품의 재질·포트 의미·물리 동작을 일괄 변경하지 않아요. 조립 대상, 선택 표시와 성공/실패는 색상 외에 모양·아이콘·문구로도 구별해요.

본문 대비 4.5:1, 큰 글자 3:1을 웹 접근성 평가 기준으로 사용해요. 비활성 요소 등의 예외를 구분하고 실제 상태별 조합을 측정해요. 몇 개 토큰이 통과했다고 전체 접근성 준수를 주장하지 않아요.

UI 글자와 코드 글자 배율을 검토해요. 확대할 때 임무·빈 작업실 카드·탭·팝업이 서로 가리지 않도록 접기/줄바꿈/스크롤과 중앙 작업 공간을 함께 설계해요. 기본 글자 크기 자체를 WCAG의 최소 크기로 오해하지 않아요.

불필요한 UI 연출 축소는 학습에 필요한 로봇 움직임이나 시뮬레이션을 끄는 기능과 구분해요. 효과음 없이도 성공·실패와 다음 행동을 알 수 있어야 해요.

## 변경할 때 남길 증거

1. 구현 변경의 소스 커밋, OS/웹, 창 크기·배율과 입력 장치를 기록해요.
2. 4개 언어의 현재 세션 전환과 저장 후 재시작을 구분해서 확인해요. 블록 초안이 있는 장면·열린 메뉴·동적 상태도 포함해요.
3. 비어 있는 장면과 조립한 장면에서 상태 보존을 확인해요. 실행 중 전환은 별도로 검증하며 미검증이면 그렇게 적어요.
4. 대상 창 크기와 글자 확대, 긴 번역에서 겹침·잘림을 실제로 확인해요. `1024×768`, `1600×1000`은 이번 감사의 사례이며 모든 장치 지원의 보장이 아니에요.
5. 키보드 Tab/Shift+Tab/Enter/Esc와 포커스 복원, 클릭 영역을 확인해요. 웹 WCAG의 CSS px를 네이티브 뷰포트 좌표와 바로 동일시하지 않아요.
6. 스크린리더, 브라우저 확대·영속 저장·시스템 테마는 해당 플랫폼에서 검사해요. 스크린샷만으로 통과 처리하지 않아요.

코드와 함께 이 문서·LOCALIZATION·관련 구현 상태를 갱신하고 [MAINTENANCE](MAINTENANCE.md)의 검사를 수행해요. 날짜 있는 감사는 당시 증거로 보존하고 새 감사로 연결해요. 정책 제안을 채택할 때만 결정 상태를 갱신해요.

## 근거와 적용 범위

- [W3C 언어 탐색](https://www.w3.org/International/questions/qa-navigation-select): 상단 위치와 해당 언어로 된 이름을 참고했어요. HTML select 전용 동작을 Godot에 그대로 적용하지 않아요.
- [WCAG 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [포커스](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html), [목표 크기](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html): 웹 평가 기준이에요. 목표 크기 AA는 24 CSS px와 예외이며, 모든 버튼 44px 의무로 요약하지 않아요.
- [Apple Dark Mode](https://developer.apple.com/design/human-interface-guidelines/dark-mode), [Settings](https://developer.apple.com/design/human-interface-guidelines/settings): Apple 플랫폼 지침을 시스템 선호 존중의 참고로 사용해요. ssok 전체 플랫폼의 인증 기준이 아니에요.
- [Nielsen 사용성 휴리스틱](https://www.nngroup.com/articles/ten-usability-heuristics/): 상태 표시, 사용자 통제, 일관성, 기억보다 인지를 평가하는 원칙이에요. 장식 유행이나 성능 수치의 보장이 아니에요.
