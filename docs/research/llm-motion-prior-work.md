# LLM을 이용한 동작 개선: 선행 연구 검토

조사일: 2026-09-15. 최신 연구 검색 범위는 **2025-01-01~2026-09-15**이고,
기반 연구는 연도 제한 없이 함께 확인했다. Exa Search로 4개 조사 축에서 검색 결과
30개를 검토했다(`sources_reviewed = 5 + 5 + 10 + 10`). 같은 논문의 프로젝트 페이지,
arXiv, 학회, 저장소를 병합해 12개 연구 후보로 정리하고, 아래 8개를 중심 근거로 선택했다.
검색 수는 요청한 결과 수의 합계이며, 독립적인 실험 재현이나 30개 논문 전체 정독을 뜻하지 않는다.

## 결론

ssok의 첫 구현은 **LLM이 제한된 동작 파라미터를 제안하고, 실제 시뮬레이션 성적을 받아
다음 후보를 수정하는 반복 최적화**가 적합하다. 이는 아래 연구들의 아이디어를 프로젝트
제약에 맞게 적용한 **설계 판단**이며, 특정 논문 알고리즘의 재현이나 성능 보장은 아니다.

LLM을 연결하는 것만으로 보행이 학습되지는 않는다. SayCan과 Code as Policies는 이미
있는 능력/API를 활용하고, Eureka는 별도의 강화학습기가 보상 함수로 정책을 학습한다.
반면 Iterative Policy Refinement는 실행 결과를 다음 프롬프트에 넣어 제어 프로그램을
개선한다. 이 구분 때문에 ssok UI의 “학습”은 초기에는 **동작 후보 탐색·평가·저장**으로
명시하고, GPT 가중치 훈련이나 실물 전이를 주장하지 않아야 한다.
([SayCan](https://say-can.github.io/), [Code as Policies](https://arxiv.org/abs/2209.07753),
[Eureka](https://eureka-research.github.io/),
[Iterative Policy Refinement](https://www.nature.com/articles/s41598-026-42091-0))

## 구현에 적용할 설계 판단

이 절은 위 연구를 ssok의 현재 코드와 결합한 **제안**이다.

1. **제어와 개선을 분리한다.** WASD → `RobotMotionProgram` → 그래프에서 찾은 서보 경로는
   유지한다. LLM 요청은 후보 사이에서만 발생하고, 실행 프레임마다 클라우드를 기다리지 않는다.
2. **생성 공간을 제한한다.** 현재 `BipedMotion`의 주기, 보폭, 기울기, 자세 같은 설명 가능한
   숫자부터 탐색한다. 형식·유한 값·범위·지원 버전을 검증하고, 로봇 본체 순간이동·힘 추가·
   물리 엔진 수정·임의 소스 실행은 출력 인터페이스에 넣지 않는다.
3. **동일 조건으로 기준선과 후보를 평가한다.** 같은 그래프, 시작 자세, 물리 설정, 시뮬레이션
   시간에서 전후진·회전·정지 결과를 측정한다. 관절 움직임만으로 이동 성공을 판정하지 않는다.
4. **넘어져서 멀리 미끄러지는 후보를 승자로 만들지 않는다.** 부호 있는 목표 방향 이동량과
   회전량 외에 최소 몸통 높이, upright, 옆 방향 드리프트, 비유한 상태, 정지 후 안정성을
   별도로 기록한다. 안전성 실패는 점수 보너스로 상쇄하지 않는다.
5. **평가된 최선을 보존한다.** 모델의 자기 평가를 점수로 쓰지 않는다. 마지막 후보와 최선
   후보를 구분하고, 개선되지 않으면 기존 것을 유지한다. 사용자 적용 전에는 원래 관절
   프로그램이나 그래프를 변경하지 않는다. 그래프가 바뀌면 이전 결과를 그대로 적용하지 않는다.
6. **학습 이력을 명시한다.** 모델 ID, 후보, 평가 조건, 실제 점수, 실패 이유, 호출 한도,
   중단 상태를 보존한다. 여기서 쌓이는 것은 동작 파라미터/실험 기록이지 GPT 가중치가 아니다.
7. **작은 자동 평가부터 검증한다.** 스키마 오류, 범위 초과, 네트워크 실패, 취소, 미지원
   로봇을 테스트한다. 오프라인 가짜 제안자 테스트와 실제 API 결과를 반드시 구분한다.

현재 관절 프로그램과 테스트의 근거는 [biped_motion.gd](../../presets/biped_motion.gd),
[biped_motion_check.gd](../../tests/biped_motion_check.gd),
[제어 문서](../CONTROLS.md), [ADR 0007](../adr/0007-blender-edit-and-manual-control.md)다.
현재 실험적 보행의 드리프트와 느린 전진은 API 연결만으로 해결됐다고 볼 수 없다.

## 가져오지 않는 것과 조사 한계

Eureka 공식 구현은 Python/Isaac Gym 기반 학습 환경을 요구한다. 따라서 Godot 런타임에
그대로 의존성을 추가하기보다는 반복 탐색 구조를 참고한다. DrEureka도 별도의 학습 파이프라인을
제공한다. 이번 검토에서 두 저장소의 표시 라이선스는 MIT였지만, 전체 의존성의 상업적 사용
권리를 감사한 것은 아니며 코드를 복사하지 않았다.
([Eureka 저장소](https://github.com/eureka-research/Eureka),
[DrEureka 저장소](https://github.com/eureka-research/DrEureka))

추가 검색 후보인 STRIDE, MotionDisco, RoboForge는 더 큰 보상 학습·궤적 최적화·모션 생성
파이프라인이어서 이번 작은 구현의 직접 기반으로 선정하지 않았다. NaviGait는 검색에는
포함됐지만 초록상 LLM 중심 방법이 아니어서 핵심 표에서 제외했다. 이는 기술의 우열 평가가
아니라 현재 범위에 대한 필터링이다.
([STRIDE](https://arxiv.org/pdf/2502.04692),
[MotionDisco](https://arxiv.org/html/2606.06139),
[RoboForge](https://arxiv.org/abs/2603.17927v2),
[NaviGait](https://arxiv.org/abs/2510.11542v2))

검색 결과에서 강의 슬라이드와 2차 요약은 사실 근거로 쓰지 않고 저자 원문으로 대체했다.
이 문헌 검토는 API 모델의 실제 사용 권한·ID, 비용, MCP 전송 방식, Godot용 서버 구현의
보안 검증을 대체하지 않는다. 또한 사족·휴머노이드 연구의 성능 수치를 ssok 4서보 이족에
전용할 수 없으며, 현재 시뮬레이터에서 반복 평가해야 한다.
