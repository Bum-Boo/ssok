# Ssok에 실제로 가져다 쓸 후보와 분리 실행 결과

확인일: 2026-09-30. [기존 로봇 과제 기술 조사](existing-robot-task-technologies-2026-09-30.md)의 후속.
사용자 요청: 기존 구현을 가져와 우리 프로젝트에 이식할 만한 것이 있는지 구체적으로 판단한다.

## 우선순위

공유 개발노트의 최신 사용자 결정은 첫 5분을 초등 고학년 기준 **서보 팔 깃발 올리기**로 완성하고, 보행/Kit 실험을 멈추며, 자연어 명령은 상자 집기 하나로 한정하는 것이다. 따라서 대형 로봇 학습 프레임워크보다 임무 진행·행동 실행·환경 자산을 먼저 검토한다. 보드 선택이나 책꽂기 지원을 이번 조사로 확정하지 않는다.

| 후보 | 가져올 범위 | Ssok 연결 지점 | 판단 |
|---|---|---|---|
| [Godot State Charts](https://github.com/derkork/godot-statecharts) · MIT | `addons/godot_state_charts`의 GDScript 애드온. `StateChart`, `CompoundState`, `AtomicState`, `Transition`과 디버거 | 현재 `src/ui/tutorial_panel.gd`는 사용자가 Next로 넘기는 설명이다. 실제 조립·배선·목표 각도 관측 이벤트를 보내 `조립→실행→성공→재도전`을 진행하는 임무 계층에 적용 가능. | **첫 경험의 흐름 관리 후보.** GDScript API를 사용하고 선택적 C# 래퍼를 제외한다. 처음 네 상태만으로 충분하면 작은 상태 머신과 비교하여 의존성 도입을 결정한다. |
| [Beehave](https://github.com/bitbrain/beehave) · MIT | `addons/beehave`의 실행 트리, `SequenceComposite`, `ActionLeaf`, `Blackboard`, 상태·디버깅 | 자연어 명령을 검증된 행동 목록으로 바꾼 뒤 `대상 확인→집기→관측` 실행. leaf만 Ssok 제어기와 연결한다. `Blackboard`는 과제 문맥이며 ConnectionGraph를 대체하지 않는다. | **다단계 행동 실행 후보.** 전체 레포의 테스트 프레임워크까지 복사하지 않는다. 검사한 스냅샷은 독립 실행 시 디버거 활성 여부 확인 수정이 필요했다. State Charts와 동시에 도입할 필요는 없다. |
| [Kenney Furniture Kit](https://kenney.nl/assets/furniture-kit) · CC0 | 선택한 가구·실내 3D 자산 몇 개 | 빈 실험 공간을 책상·방 같은 맥락으로 구성. 로봇의 조립 단위와 물리 형상은 Ssok 정의를 유지. | **화면 분위기를 바꾸는 직접 재사용 후보.** 전체 140개를 모두 번들하지 않고 필요한 것만 고른다. 실제 모델별 크기·재질·충돌·GL/Web 비용은 import 후 확인해야 한다. |
| [Kenney Interface Sounds](https://kenney.nl/assets/interface-sounds) · CC0 | 선택·스냅·성공에 사용할 짧은 소리 | 실제 부품 연결 또는 관측된 성공 시 재생. 입력 잠금·중복 이벤트에서는 중복 재생하지 않는다. | **상호작용 반응을 개선하는 직접 재사용 후보.** 공식 페이지는 100개 파일을 제공한다. 아직 다운로드·청음·앱 적용하지 않았다. |

MIT 코드를 수정·재배포할 때 해당 저작권·허가문을 보존한다. 자산은 위 개별 팩의 CC0 표기를 확인했다. 가져올 버전·파일·변경사항을 고정하고 기존 `THIRD_PARTY_NOTICES.md`와 배포 라이선스 복사 과정에 연결한다. 이번에는 후보를 앱에 편입하지 않았으므로 그 파일에 도입 완료로 추가하지 않았다.

State Charts의 저장소에는 별도 라이선스인 데모 그림도 있다. 재사용 단위는 애드온이며 데모 자산은 복사하지 않는다. 라이선스가 다른 로봇 모델·학습 가중치를 저장소 코드의 MIT/Apache 라이선스로 간주하지 않는다.

## 실제로 돌려 본 범위

Ssok 워크트리 밖 `/tmp/ssok-reuse-shortlist-20260930/probe`에 두 애드온을 받아 **현재 설치된 Godot 4.7.2 `ed1daf0bf`**로 실행했다. 프로젝트 설정은 GL Compatibility다. headless 실행이므로 실제 화면 렌더링을 검사한 것은 아니다.

- Beehave: `fe589153fa780a3f88989578ceb5f539afffb7c2`, `godot-4.x` 브랜치 스냅샷, `plugin.cfg` 표기는 `2.9.4-dev`. 확인 당시 최신 공개 릴리스는 `v2.9.3`; **릴리스 v2.9.3을 테스트했다고 쓰지 않는다.**
- State Charts: `76d226a3efac66a72aea825382b320c94808f409`, `main` 브랜치 스냅샷, `plugin.cfg` 표기는 `0.22.5`. 선택적 `csharp/` 래퍼는 제외했다.
- 애드온 import는 오류·경고 없이 종료했다. 완성 앱에 플러그인을 설치하거나 장면을 바꾸지 않았다.
- 최초 드라이버에는 Beehave singleton 초기화가 빠졌고, State Charts의 frozen 상태에 이벤트를 보내 명시적 거부 오류가 발생했다. 이를 애드온 결함으로 집계하지 않는다. 두 singleton을 초기화하고 frozen 동안 이벤트를 보내지 않는 사용 계약으로 드라이버를 고쳤다.
- 보완된 드라이버에서 **원본 Beehave는 비활성 디버거로 메시지를 보내거나 캡처를 등록하는 오류를 냈다.** 행동 검사 12개가 모두 참이어도 원본 실행을 깨끗한 통과로 기록할 수 없다.
- 분리 복사본의 디버그 메시지 전송 조건과 메시지 캡처 등록에 `EngineDebugger.is_active()` 조건을 추가했다. 그 결과 **검사 12/12, 전체 로그 엔진/스크립트 오류·경고 0**으로 종료했다. State Charts 소스는 수정하지 않았다.

검사한 것은 Beehave의 진행 중 상태, 뒤 행동 대기, 중단 전달, 실패 시 뒤 행동 차단, 순차 성공과 State Charts의 시작·이벤트 전환·성공·재도전이다. 행동 leaf는 결과를 돌려주는 합성 동작이다. **실제 로봇 집기·네트워크 취소·자연어 이해·Web 실행·시각 디버거는 미검증**이다. 이 두 줄의 조건 추가가 연결된 에디터 디버깅에 미치는 영향도 후속 검사에 포함한다.

증거: [분리 실행 자료](reuse-probe-2026-09-30/README.md). 수정 diff, 드라이버, 원본 실패/부분 수정/최종 로그, 출처와 파일 해시를 보존했다. 앱 소스와 기존 보행 WIP, 사용자 언어팩에는 변경이 없다. 유료 요청·배포도 없다.

## 지금 통째로 이식하지 않을 것

- **MoveIt Task Constructor:** 유용한 경로 계획 구현이지만 ROS 2, 로봇 기구학 표현, 관절·그리퍼·충돌·제어기 어댑터가 먼저 필요하다. 현재 첫 깃발 과제에 붙이면 연결 작업이 커진다. 책 배치 경로가 실제로 필요해지는 단계에서 평가한다.
- **BEHAVIOR / AI2-THOR:** 생활 과제·상태 관측·성공 판정 방식은 참고 가치가 높다. 시뮬레이터 전체와 자산을 Godot 앱으로 옮기는 작업은 별도 규모다.
- **LeRobot / openpi:** 학습과 이미 학습된 정책의 적용 후보지만, 지금의 첫 5분 흐름과 짧은 명령 과제의 선행 의존성은 아니다.

## 다음 이식 단위

첫 제품 변경은 가구 몇 개·짧은 효과음·한 임무의 관측 기반 진행으로 제한한다. State Charts 도입을 선택하면 정확한 버전과 MIT 문서를 포함하고, 조립/배선 신호와 결과 관측을 연결한다. 제품 문자열은 EN/KO/ZH_CN/JA를 같이 갱신한다. 자연어 명령의 다단계 실행이 필요할 때 Beehave와 위 수정의 정식 도입을 검토한다.

기존 [제품 경험 기준](../PRODUCT_EXPERIENCE.md), [자연어 수행 설계](../NATURAL_LANGUAGE_TASKS.md), ADR의 엔진·ConnectionGraph·보드 분리·물리 기준을 유지한다. 라이브러리가 임무 진행을 담당해도 성공은 실제 관측으로 판정하며, AI 사용료 고지는 별도 제공자 연결에 그대로 적용한다.
