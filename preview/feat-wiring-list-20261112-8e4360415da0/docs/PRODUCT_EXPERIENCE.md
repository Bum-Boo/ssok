# Ssok 놀이 경험과 AI 연결 개발노트

> 날짜가 있는 조사·요구 기록이다. 이후 구현·제품 결정은 [STATUS](STATUS.md)를 따른다.
갱신: 2026-09-30 · Codex · 사용자 요청에 따른 조사·제안·후속 개발 기준.

**추가 사용자 요구:** 앱 내 명령창에 `선반에 저 책을 꽂아줘`라고 입력하면 AI가 장면 속 로봇으로 수행한다.
이 요구를 중심 기능으로 반영한 [자연어 명령·로봇 수행 설계](NATURAL_LANGUAGE_TASKS.md)를 함께 읽는다.
아래의 AI 제안 기능만으로 이 요구를 완료했다고 볼 수 없다.

## 이번에 확인한 결론

Ssok의 입구를 **작은 로봇 장난감을 만들고 도전하는 책상 위 작업실**로 발전시킨다.
완성 예시를 먼저 만져 보고, 한 부분을 바꾸고, 결과를 비교하는 기존 탑다운 학습 비전을 살린다.
핵심 반복은 `해보고 싶은 장면 → 조립/수정 → 실행 → 결과 확인 → 한 부분 바꿔 재도전`이다.
대상 연령과 구체적인 미술 방향은 아직 확정되지 않았다. 어린이 전용 말투나 과한 캐릭터화는 가정하지 않는다.

이번 결과는 실제 화면 진단, 출처 조사, 콘텐츠 설계와 개발 규칙이다. 아래 신규 임무·리플레이·AI 연결 화면은 **제안이며 미구현**이다.
2026-09-30 로컬 `3a142eb`와 당시 작업 트리에서 읽고 실행했다. 별도 세션이 소유한 Kit 물리 WIP는 편집하지 않았다.
배포 상태와 물리 성공률의 정본은 `RELEASE_PLAN.md`와 해당 실험 기록이다.

## 1. 지금 화면에서 무엇이 심심한가

이번 실행의 [화면 4장과 진단](research/playful-ux-2026-09-30/README.md)을 근거로 한다.

| 단계 | 관찰한 상태 | 먼저 바꿀 경험 |
|---|---|---|
| 1. 첫 진입 | 시작 버튼은 있지만 넓은 빈 바닥, 부품 목록, 코드가 동시에 등장한다. 무엇을 해내는지 보이지 않는다. | 완성 로봇의 짧은 실제 동작과 `깃발 올려 보기`를 앞에 둔다. 자유 조립과 이어 하기도 남긴다. |
| 2. 튜토리얼 | 1/11부터 부품 규격과 Blender 파일 구조를 설명한다. 읽는 동안 조립을 못 한다. | 한 동작씩 실제 장면에서 안내한다. `이 구멍에 끼워요` → 끼우면 다음 단계. 구현 설명은 도움말로 옮긴다. |
| 3. 실행 | 로봇 모형은 개성이 있지만, 바닥에 목적지나 진행 표시가 없다. 양옆 편집 패널도 계속 자리를 차지한다. | 실행할 때 임무 목표, 시작/다시 하기, 짧은 결과만 남기고 장면을 넓힌다. 자세한 값은 펼쳐 본다. |
| 4. AI 탐색 | 유료 OpenAI 요청 동의와 취소 과금 안내는 이미 있다. 연결·목표·측정 규칙이 개발자 용어로 설명된다. | 하고 싶은 도움을 먼저 고르고 서비스/계정/비용을 실행 직전에 확인한다. 제공자별 과금 방식과 정책 링크를 넣는다. |

우선순위는 목표와 재도전 흐름, 조작 반응, 장면과 글의 개성 순이다. 색 변경만으로 해결됐다고 판정하지 않는다.

## 2. 콘텐츠와 첫 5분

첫 구현 후보는 **서보 팔로 깃발 올리기**다. 기존 서보 팔, 배선 그래프, 코드 실행을 재사용한다.
새 보행 제어기를 기다리지 않고 조립부터 성공까지 관통하는 작은 과제를 만들 수 있다.
깃발은 처음에는 팔 끝의 시각 부착물로 검토하고, 질량·충돌을 추가하면 별도 물리 검증을 한다.

| 순서 | 플레이어가 하는 일 | 화면에 줄 피드백 |
|---|---|---|
| 1 | 완성 예시의 팔을 움직여 본다. | 성공 장면을 먼저 보고 직접 해보기를 선택한다. |
| 2 | 빠진 팔 하나를 끼운다. | 호환 포트 표시, 실제 연결 순간 짧은 소리와 강조. 키보드로도 연결한다. |
| 3 | 모터를 보드 핀에 연결한다. | 해당 선과 핀이 강조되고 잘못 연결했으면 위치와 고칠 일을 알려 준다. |
| 4 | 코드의 각도 한 숫자를 바꾸고 실행한다. | 실제 관절이 목표 구간에 들어오면 깃발 도달을 판정한다. 목표 명령만 보고 성공 처리하지 않는다. |
| 5 | 더 높이/천천히/다른 순서로 바꾼다. | 직전 실행과 달라진 점, 다시 하기, 내 로봇에 이름 붙이기. |

처음 60초 안에 첫 동작, 5분 안에 한 번의 성공과 자발적 수정 1회를 **검증할 가설**로 둔다. 현재 달성한 수치가 아니다.
완성 예제를 자유롭게 뜯어보는 경로도 제공한다. 긴 튜토리얼을 끝내야 자유 조립을 열어 주는 방식은 피한다.

후속 콘텐츠는 실제로 가능한 동작 범위에 맞춘다.

| 후보 | 재미의 질문 | 선행 조건 |
|---|---|---|
| 깃발 올리기 | 각도를 바꾸면 어디까지 올라갈까? | 서보 팔 + 실제 각도 판정 + 짧은 안내. 첫 구현 대상. |
| 30cm 첫걸음 | 선까지 넘어지지 않고 갈 수 있을까? | 학습 이족의 전진만 사용. 실제 거리/낙상 판정. 후진·회전 미지원 표시. |
| 상자 들어 올리기 | 같은 팔로 더 안정되게 들려면? | 수정 토크 모델의 Kit 집기 재검증 결과 사용. 걷기와 조합하지 않는다. |
| 구조물 바꿔 보기 | 같은 부품으로 다른 모양을 만들 수 있을까? | 기존 구조 키트 재사용. 하중 견디기 점수는 실제 하중 평가기가 생긴 뒤 추가. |
| 같은 부품, 다른 해법 | 친구와 무엇을 다르게 만들었을까? | 기존 JSON 공유에서 시작. 향후 조건·버전·실제 결과가 포함된 공유물과 리믹스 연결. |

공개 관심을 끌 콘텐츠도 같은 반복을 보여 준다. `문제 장면 → 첫 시도 → 한 부분 수정 → 달라진 결과`의 짧은 실제 앱 영상과 재현용 프로젝트를 한 쌍으로 만든다.
실패 장면도 사용자가 선택해서 남기게 한다. 자동 공개·게시나 순위 경쟁을 먼저 만들지 않는다.
정기 도전은 충분한 임무가 생긴 뒤 도입한다. 보상은 꾸미기·전시처럼 창작의 흔적을 남기는 방향을 먼저 검토한다.

## 3. 손맛과 화면 방향

- **Ssok만의 반응:** 포트가 가까워질 때 미리 보기, 실제 연결되면 짧은 `쏙` 소리와 포트 강조, 배선되면 연결 경로 표시. 클릭마다 같은 폭죽을 띄우지 않는다.
- **공간:** 책상 위 작은 작업판, 목표 테이프, 부품 트레이 같은 역할 있는 요소를 검토한다. 장식은 물리 충돌에 영향을 주지 않는 시각 계층에 둔다.
- **위계:** 조립 중에는 필요한 부품·배선·되돌리기, 실행 중에는 목표·진행·정지·다시 하기가 먼저 보이게 한다. 코드와 수치는 계속 접근 가능하게 한다.
- **실패:** `실패했습니다`에서 끝내지 않고 실제 관측과 다음 행동을 연결한다. 예: `목표 선 앞에서 넘어졌어요. 마지막 장면을 볼까요?` 원인이 검증되지 않았다면 원인을 단정하지 않는다.
- **재시도:** 편집 원본과 마지막 시도를 보존하고 같은 조건으로 다시 실행한다. 리플레이는 녹화 재생인지 재시뮬레이션인지 구별한다.
- **접근성:** 소리 없이도 연결과 성공을 알 수 있게 한다. 효과 줄이기, 명확한 초점, 색 이외의 상태 표시를 검토한다. 큰 화면 캡처만으로 작은 화면·키보드 접근성 통과를 선언하지 않는다.
- **물리 원칙:** 움직임을 좋아 보이게 하려고 몸체 위치나 성공 수치를 꾸미지 않는다. [ADR0001](adr/0001-engine-and-deployment-targets.md), [0002](adr/0002-connection-graph-single-source-of-truth.md), [0003](adr/0003-hybrid-physics-modes.md)를 유지한다.

## 4. AI 티를 줄이는 개발 기준

여기서 말하는 AI 티는 출처를 숨기는 일이 아니라, 제품과 상관없는 상투적인 화면·문구·동작을 줄이는 일이다.

1. **Ssok의 실제 사물을 쓴다.** 부품 구멍, 배선, 작은 모터, 조립 흔적과 플레이어가 지은 이름이 시각 언어의 출발점이다.
2. **화면마다 역할을 정한다.** 모든 정보를 똑같은 카드, 같은 크기의 아이콘, 같은 문장 길이로 배치하지 않는다. 잘 알려진 탐색·접근성 패턴은 유지한다.
3. **기본 생성 스타일을 이유 없이 쓰지 않는다.** 보라 그라데이션·유리 패널·반짝이 아이콘 등을 금지색 목록으로 취급할 필요는 없지만, Ssok의 행동을 설명하는 근거 없이 채택하지 않는다.
4. **실제 동작을 보여 준다.** 실제 앱 화면과 실제 성공/실패를 사용한다. 장식용 가짜 상태, 작동하지 않는 버튼, 근거 없는 성과 수치를 넣지 않는다.
5. **짧은 해요체로 쓴다.** `모션 최적화 수행` → `움직임 바꿔 보기`, `학습 성능 향상` → 관측한 사실을 구체적으로 표현한다. `예제`, `답지`, 반말과 해요체가 섞인 현재 표현은 사용 맥락에 맞춰 정리한다.
6. **측정과 추측을 구분한다.** `12cm 더 갔어요`는 실제 비교값이 있을 때만 쓴다. 더 빠르다는 이유만으로 더 안정적이라고 말하지 않는다.
7. **AI 도움은 명시한다.** `AI 제안`, 제공자, 보내는 데이터와 비용은 알아볼 수 있게 남긴다. 플레이어 대신 자동으로 성공시키지 않는다.
8. **사람이 소리 내어 읽고 직접 해본다.** 제목을 가려도 Ssok의 장면으로 보이는지, 한 문장으로 다음 행동이 설명되는지 확인한다. 이것은 검토 질문이며 AI 탐지 기준이 아니다.

| Codex/Claude → Ssok MCP | stdio 어댑터 구현됨. describe/start/get/cancel 네 도구. 이번 실제 SDK 검사 14개 통과. | 호스트에 수동 등록해야 한다. MCP는 AI 자체가 아니다. 생성과 실제 물리 평가 범위는 기존 제한대로다. |
| Ssok 안에서 Codex CLI 사용 | 미구현. 공식 App Server를 외부 로컬 브리지 뒤에 연결하는 방식 검토 가능. | 앱 UI, 인증 상태, 세션·승인·중단·사용량 연결이 필요하다. |
| Ssok 안에서 Claude CLI 사용 | 미구현. 공식 Agent SDK 또는 `claude -p`를 외부 브리지에서 사용하는 방식 검토 가능. | 공식 인증 경로와 최신 정책 확인. 구독 토큰을 임의 API 자격증명으로 재사용하지 않는다. |
| 다른 클라우드/로컬 모델 | 미구현. 제공자 어댑터 확장 후보. | 각 서비스의 응답 형식·정책·요금·사용량 보고를 검증해야 한다. 로컬 모델도 장비와 모델 라이선스 조건이 있다. |

현재 컴퓨터에서 확인한 Codex 전역 MCP 설정과 Claude 최상위 MCP 설정에는 Ssok 항목이 없었다. 모든 프로젝트/관리자/플러그인 설정을 전수 조사한 것은 아니다.
`ssok-release`에는 `.venv-motion`이 없어서 기존 `~/Projects/ssok/.venv-motion/bin/python`으로 이 작업 트리의 MCP 검사를 실행했다.
실제 Codex/Claude 대화에서 종단간 호출한 검증은 아니다. 사용자 계정 설정은 바꾸지 않았다.

**연결 방향을 혼동하지 않는다.** 외부 CLI가 현재 MCP를 부르면 그 서버의 평가 세션을 사용한다. 열린 Godot 편집기를 직접 조작하거나 현재 UI 세션과 자동 동기화하지 않는다.
호스트 모델 사용량과, MCP 서버를 `--live`로 켰을 때 내부 OpenAI 요청 비용은 **서로 별도**다. 둘 다 켜면 두 비용 경로가 생길 수 있다.
기존 MCP는 외부 AI가 제안한 임의 정책을 앱에 바로 주입하는 통로가 아니다. 이 부분을 확장하려면 명시적인 검증·전송 설계가 필요하다.

### 권장 연결 구조 (미구현 설계)

```text
Ssok의 선택형 AI 도움 패널
  → 비동기 요청 → 사용자 컴퓨터의 로컬 브리지
                  ├─ Codex App Server (공식 로그인)
                  ├─ Claude Agent SDK / CLI (공식 로그인)
                  └─ 제공자 API 어댑터 (별도 API 인증)
  ← 제한된 제안 → 스키마 검사 → 실제 시뮬레이션 → 사용자 선택 적용
```

브라우저에서 로컬 CLI를 직접 실행할 수는 없다. 데스크톱 동반 브리지 또는 인증된 서버가 필요하다.
현 웹 클라이언트의 `OS.execute` 금지와 GDScript·GL Compatibility 원칙을 유지한다.
공개 웹 → 로컬 브리지 경로는 브라우저별 보안 정책·HTTPS·Origin·인증의 별도 검증 대상이다.
공유 서버의 API 키는 서버에 두고 사용자별 인증과 호출 한도를 둔다.
새 제공자는 ADR0008의 고정 제공자 결정을 확장하므로 구현 전에 후속 ADR을 남긴다. 이번 조사로 기존 결정을 변경하지 않는다.

AI에는 **명령을 받아 로봇 행동을 실행하는 역할**과 `무엇을 바꾸면 좋을까?`에 답하는 도움 역할을 둔다.
전자에 필요한 대상 식별·행동 실행기·결과 검증은 현재 없다. 상세 구현 순서와 승인 경계는 [명령창 설계](NATURAL_LANGUAGE_TASKS.md)를 따른다.
자유로운 터미널·파일 접근과 임의 생성 코드 자동 실행은 기존 제한 밖이다.

### 공식 문서에서 확인한 범위

- [Codex App Server](https://learn.chatgpt.com/docs/app-server): 프로그램에서 Codex 세션을 제어하는 인터페이스와 기본 stdio 경로. 실제 앱에 넣을 때 설치 버전과 인증 기능을 다시 확인한다.
- [Codex 요금 안내](https://learn.chatgpt.com/docs/pricing): 플랜 사용량과 API 키 과금은 구별된다. 추가 크레딧·초과 사용 조건은 연결된 계정에 따른다.
- [Claude 프로그램 호출](https://code.claude.com/docs/en/headless): Agent SDK와 `claude -p` 경로, 구조화 출력·도구 승인 기능.
- [Claude SDK 구독 정책](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan): 열람 당시 상단의 **2026-06-15 변경 보류 안내**가 현재 설명이다. SDK/`claude -p`/SDK 경유 외부 앱은 기존 구독 사용 한도를 사용한다고 명시한다. 아래의 월별 SDK 크레딧 표는 보류 전 보존 내용이라 현재 혜택으로 인용하지 않는다. API 키는 사용량 과금이다.
- [Claude MCP](https://code.claude.com/docs/en/mcp): 외부 도구 서버를 등록하는 경로. 이것만으로 Ssok 안에 Claude가 내장되지는 않는다.

정책 확인일: **2026-09-30**. 계정별 허용, 국가·관리자 제한, 실제 청구 금액은 확인하지 않았다. 고정 요금표를 앱에 복사해 영구 보장하지 않는다.

## 6. 비용 고지와 동의 설계

현재 `motion_lab_panel.gd`에는 검색별 유료 OpenAI 요청 동의, 취소 후에도 진행 중 요청이 과금될 수 있다는 문구가 있다.
새 제공자 화면은 다음 세 지점을 함께 구현해야 한다. 아래는 **현재 구현 설명이 아니라 완료 기준**이다.

1. **연결할 때:** 서비스·연결 계정·인증 방식·`구독 사용량 / API 사용량 과금 / 로컬 / 확인 불가` 표시, 공식 정책 링크와 확인일.
2. **실행 직전:** 제공자와 모델, 보내는 데이터, 최대 요청 수, 확인 가능한 예상 비용과 명시적 동의. 현재처럼 선택 해제된 상태에서 시작한다. 연결/모델/과금 방식이 바뀌면 다시 확인한다.
3. **실행 중·후:** 누적 요청 수와 제공자가 보고한 사용량, 중단 상태, 청구 내역 확인 링크. 알 수 없는 금액은 `확인할 수 없어요`로 표시하며 0원으로 쓰지 않는다.

화면용 기본 문구 초안:

> 연결한 AI 서비스의 요금제와 사용량 정책에 따라 구독 사용량이 차감되거나 별도 요금이 발생할 수 있어요. 요금은 해당 서비스에서 청구해요. 실행 전에 계정과 요금 정책을 확인해 주세요.

실행 직전 추가 문구:

> 이번 요청은 {서비스}의 {모델}로 보내요. {요청 내용과 조립 정보 등 실제 전송 항목}을 전송해요. 최대 {횟수}회 요청해요. 중단해도 이미 보낸 요청에는 요금이 발생할 수 있어요.

동의: `사용량과 비용 안내를 확인했어요` · 실행: `AI에게 제안 받기` · 정책: `{서비스} 요금 확인`.
버튼을 누르는 순간 어떤 작업을 요청하는지 표현하고, 단순 연결 확인에서 유료 생성을 시작하지 않는다.

- 로그인만으로 API 사용까지 무료라고 표시하지 않는다. mock/AI 미사용 실행과 호스트 AI 사용을 분리한다.
- 요청 횟수·토큰 상한은 금액 상한과 다르다. 제공자가 확실한 금액 상한을 보장하지 않으면 `최대 ○원 보장`이라고 쓰지 않는다.
- 잔여량을 읽을 수 없으면 공급자 페이지로 안내한다. 구독 소진 후 유료 API로 자동 전환하거나 다른 모델로 몰래 바꾸지 않는다.
- 실패/시간초과 요청을 자동 재전송하지 않는다. 실행 여부 불명 상태를 구분하고 취소 완료와 연결 끊기를 혼동하지 않는다.
- 제안만으로 코드·저장 프로젝트를 자동 변경하지 않는다. 사용자가 명령창에서 요청한 시뮬레이션 과제는 이미 확인한 제공자·비용 범위에서 수행하게 한다. 단계마다 같은 허락을 다시 묻지 않는다.
- 실제 UI 반영 시 영어와 `ko/zh_CN/ja`를 같은 변경에서 갱신하고 비용 의미가 동일한지 검수한다.

## 7. 계속 반영하는 방법

[기존 로봇 과제 기술 조사](research/existing-robot-task-technologies-2026-09-30.md)에 명령 수행을 위한 재사용 후보와 책꽂기 선행 사례를 기록했다. 새 행동 실행기·계획기·학습 도구를 만들기 전에 관련 기존 기술의 적용 가능성과 연결 비용을 확인한다.

[실제 이식 후보와 분리 실행 결과](research/reuse-shortlist-2026-09-30.md)는 첫 깃발 과제에 쓸 State Charts·Kenney 자산과 후속 행동 실행용 Beehave를 구체화한다. 애드온의 합성 네이티브 검사와 실제 앱/Web/물리 검증을 구별한다.

`AGENTS.md`에서 이 문서를 UI·콘텐츠·AI 연결 작업의 사전 읽기로 연결한다.
인터넷을 상시 자동 수집하거나 모델 자체를 학습시키는 설정은 아니다. **관련 변경을 할 때마다** 아래 기록을 갱신하는 운영 방식이다.

변경마다 다음 여섯 줄을 개발노트/PR에 남긴다.

```text
해결하려는 사용자 장면:
참고 출처와 확인일 / 근거의 한계:
채택한 원칙과 이번에 바꾼 점:
실제 전후 화면 또는 실행 증거:
검증 결과 / 언어팩 / 비용 고지 영향:
남은 문제와 다음 확인:
```

기존 근거로 충분하면 불필요하게 조사부터 반복하지 않는다. 새 문제나 반례가 있으면 해당 주제의 커뮤니티 의견과 원자료를 추가한다.
AI 서비스 인증·가격·정책은 구현과 출시 때 공식 문서로 다시 확인한다. 새 근거가 기존 판단과 충돌하면 날짜와 이유를 남긴다.
실제 적용되지 않은 아이디어를 반영 완료로 기록하지 않는다.

가벼운 첫 사용자 검증은 대표 사용자 5~8명 정도의 관찰로 문제를 찾는 데 사용한다. 통계적 우월성이나 유지율 입증으로 부르지 않는다.
첫 동작까지 시간, 첫 성공 비율, 도움 없이 두 번째 시도한 비율, 수정 후 재실행 비율을 본다.
원격 분석은 아직 없으므로 개인정보 수집을 자동 추가하지 않는다. 처음에는 동의한 테스트의 관찰 기록으로 충분하다.
